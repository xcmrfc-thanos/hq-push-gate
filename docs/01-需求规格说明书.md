# 需求规格说明书

> 项目：hq-push-gate 智析平台 | 版本：V2.1 | 用途：论文/技术体现（非商业）
>
> 统一设计和验收口径见 [07-设计基线与验收口径](./07-设计基线与验收口径.md)。

## 1. 背景与目标

构建一个面向高可用、高性能、高并发场景的多市场行情预警推送平台，作为分布式系统架构设计与实现的技术验证载体：

1. 验证流式计算（Flink）在海量规则匹配场景下的低延迟处理能力；
2. 验证 WebSocket 集群在大规模长连接推送场景下的并发承载能力；
3. 验证 OLAP 存储分层（ClickHouse + Doris）在百亿级时序数据下的查询能力；
4. 通过混沌演练与压测实验，产出可量化的系统指标（论文实验数据）。

数据策略：**东财实时快照 + Baostock 历史回填 + 自研模拟 tick 发生器**（ADR-036；MiniQMT 主力源暂缓），真实数据支撑开发验证，sim 源供压测可控负载。

## 2. 用户角色

| 角色 | 说明 | 主要入口 |
|---|---|---|
| 游客 | 浏览行情、延迟快照 | PC / H5 |
| 注册用户 | 配置预警、订阅推送、分组管理、AI 筛选 | PC / H5 |

## 3. 功能需求

### FR-1 行情数据

| 编号 | 需求 | 优先级 |
|---|---|---|

| FR-1.2 | K线：1m/5m/15m/30m/60m/日线，周期闭合即推送 | P0 |
| FR-1.3 | 历史K线查询：按市场+标的+周期+时间范围 | P0 |
| FR-1.4 | 内置技术指标：MACD/KDJ/RSI/BOLL，随K线计算展示（T1 批规划态：后端指标引擎随 Branch 14 收尾，前端暂无指标图） | P1 |
| FR-1.5 | 自选股列表实时刷新 | P0 |
| FR-1.6 | 市场总览：指数、涨跌家数、板块热度 | P2 |

### FR-2 预警引擎

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-2.1 | 价格条件：高于/低于/区间 | P0 |
| FR-2.2 | 涨跌幅条件（日内/周期内） | P0 |
| FR-2.3 | 指标条件：如 RSI>80、MACD 金叉（内置指标枚举；T1 批规划态，随 Branch 14 日频引擎落地） | P1 |
| FR-2.4 | 规则 CRUD、启用/停用；**新增规则热生效，不重启计算任务** | P0 |
| FR-2.5 | 防抖冷却：同一规则命中后 N 秒内不重复触发（用户可配） | P0 |
| FR-2.6 | 命中记录持久化 + 分页查询；未命中数据不入告警表但行情照常入库 | P0 |
| FR-2.7 | 自定义公式（受限表达式沙箱，M3 阶段） | P2 |

### FR-3 消息推送

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-3.1 | WebSocket 实时推送预警与行情，断线自动重连（指数退避） | P0 |
| FR-3.2 | 离线补拉：重连后按时间点补拉错过的告警（REST 兜底） | P0 |

| FR-3.4 | 公众号模板消息（适配器，可选，非论文核心） | P3 |

### FR-4 标的分组

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-4.1 | 手动分组：建组、加入/移出标的 | P1 |
| FR-4.2 | 条件自动分组：满足指标条件的标的自动入组（离线批算） | P2 |

### FR-5 AI 智能筛选（可选亮点，M3 阶段）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-5.1 | 自然语言转结构化筛选条件（NL2Condition），条件下推 Doris 执行，禁止大模型编造结果 | P2 |
| FR-5.2 | 筛选结果一键保存为分组 / 生成预警规则 | P3 |

### FR-6 管理后台

用户管理、数据源健康监控（断流告警）、链路观测（Kafka 积压/Flink 延迟/推送成功率）、压测任务控制台（启停模拟源、调压、批量造用户/规则）。P1。

| 功能 | PC Web | H5 | 说明 |

| 历史K线查询 | 完整 | 完整 | 同一查询 API |
| 分组管理 | 完整 | 基础 | |
| AI 筛选 | 完整 | 基础对话 | |
| 管理后台 | 独立路由域 | 不支持 | 仅 PC |

> 实现现状（审计注记）：H5 当前落地**行情看板 + 告警中心**两页（`apps/h5/src/app`）；
> 上表个股 K 线/规则管理/AI 筛选等行为 H5 目标矩阵（规划态），随 M5 选股演进补齐。

H5 专项要求：

1. 弱网适应：WS 断线重连 1s 起指数退避（上限 60s）；重连成功先 REST 拉最新快照再续订；
2. 流量与电量：页面不可见时自动退订行情、只保留告警通道；
3. 首屏：CDN + gzip/brotli + 路由级代码分割，首屏 ≤ 2s（4G 弱网 ≤ 4s）。

## 6. 约束

1. 团队技术栈：Java/Go/Python/TS/React 全栈可用（按场景分工，不追求单语言）；
2. 论文实验资源：benchmark-small 使用 ≤ 10~15 台 8C16G 虚机；百万连接使用独立 benchmark-large 资源；
3. 开发环境：单机 Docker Compose 可跑通全链路最小拓扑；
4. 所有消息与表结构强制携带 `market` 字段，预留港股/美股扩展（本论文仅实现 A 股 + 模拟源）。
