# 容量规划与性能压测方案

> 项目：hq-push-gate 智析平台 | 版本：V2.1 冻结基线 | 本文档为论文实验设计的核心
>
> 环境和验收统一口径见 [07-设计基线与验收口径](./07-设计基线与验收口径.md)。

## 1. 容量模型

### 1.1 输入假设（模拟源可编程设定）

业务规模按注册用户和峰值在线连接双指标分档；详细阶段定义和扩容触发条件见 [07-设计基线与验收口径](./07-设计基线与验收口径.md) §4。

| 参数 | 基准值 | 压测峰值 |
|---|---|---|
| 标的数 | 5,000（A 股规模） | 5,000 |
| tick 速率 | 3 万条/s（快照级均值） | 10 万条/s（含 30s×10 倍脉冲） |
| 活跃预警规则 | 10 万条 | 100 万条 |
| WS 并发连接 | 10 万 | benchmark-large 单独验证 100 万（分级：10w→50w→100w） |
| 行情查询 QPS | 1,000 | 10,000 |
| 历史数据灌入 | AKShare 全市场日线+分钟线 + 模拟回填 | 百亿行（模拟） |

### 1.2 数据量推算

资源约束下的 benchmark-small 只验证实时链路和 10 万连接；百亿行数据与百万连接属于独立 benchmark-large/离线实验，不在同一套 8C16G 小集群中同时验收。benchmark-large 至少提供 8 个专用 8C16G WS 节点和 2 个 8C16G 压力源节点。

```
tick 行数/年  = 速率 × 交易日秒数
             = 30,000/s × 14,400s × 250 日 ≈ 1,080 亿行/年（峰值模型）
存储(压缩后)  ≈ 1,080e8 × 20B ≈ 2.2 TB/年
3 年累计量    ≈ 6~7 TB（热 1 年 ≈2.2TB 于 CK，TTL 12 个月滚动；更冷归档 S3）
```

> 说明：原文"百亿/3年"对应快照级行情；逐笔级模拟可达千亿行。架构按 10^11~10^12 行设计（CK 水平分片 + 分区 + TTL + S3 归档），论文灌入规模取 100~500 亿行验证查询性能随数据量的变化。

### 1.3 其它容量

| 项 | 推算 |
|---|---|
| Kafka tick_raw 流量 | 10w msg/s 按消息体、协议头和 RF=3 实际测量；6 MB/s 仅为裸 payload 下界 |
| Flink 规则状态 | 100w 规则 × ~200B ≈ 200MB（RocksDB），checkpoint 增量秒级 |
| ws_push 扇出 | 5000 活跃 symbol × 8 网关实例 ÷ 0.5s = 8w msg/s |
| MySQL 规则表 | 100w 行 + 索引 < 1GB |
| Redis 快照 | 5000 symbol × 1KB = 5MB + 订阅关系（10w 用户×50 symbol）≈ 数百 MB |

## 2. 集群规格（论文实验环境，10~15 台 8C16G）

| 组件 | 规格 | 部署 |
|---|---|---|
| K8s master | 3×4C8G | 独立小节点（或托管） |
| Kafka | 3 broker（8C16G 混部 ns-realtime） | RF=3 |
| Flink | 2 JM(ha) + 4~8 TM（各 4C8G） | on K8s |
| ClickHouse | 2 分片 × 2 副本（各 8C16G + 500G SSD） | 混部或独立 |
| Doris | 3 FE + 3 BE | 混部 ns-query |
| MySQL | 1主1从（4C8G） | 半同步 |
| Redis Cluster | 3主3从（混部） | 每分片 4G |
| APISIX | 2×2C4G | ns-query |
| ws-gateway | benchmark-small：按 10 万总连接配置；benchmark-large：8 个专用 8C16G 节点承载 6×4C16G 工作实例 + 2 个冗余实例，单实例按 20 万规划 | ns-push，双可用区打散 |
| 业务服务/notify/quote-push/ingest | 各 2~4×2C4G | HPA |
| 模拟源/压测控制器 | 2~4×4C8G | ns-offline，与被测集群资源隔离 |

## 3. 压测工具链（内建，ADR-012）

| 工具 | 用途 |
|---|---|
| sim-tick-generator | 模拟行情源：标的数/速率/脉冲/价格游走（GBM 可复现，固定随机种子） |
| ws-client-simulator | Go 编写，单进程 5w 连接（多协程）；**100w 连接需 8 pods × 12.5w**，每 pod 独立 IP（规避 64k 临时端口上限：1M 连接 ≥ 16 源 IP）；订阅 profile 可配（10% FULL / 30% SLOW / 60% ALERT_ONLY，匹配分级推送模型） |
| user/rule seeder | 批量注册压测用户、灌入规则（按 symbol 热点分布 zipf 可配） |
| k6 / wrk2 | REST 查询压测（开环模式测尾延迟） |
| Chaos Mesh | 故障注入（kill/网络分区/IO 打满） |
| Prometheus + Grafana | 全指标采集，实验期间快照存档 |

> 实现现状（审计注记）：上表为目标态工具链。已落地：`bench/tick-source`（模拟源，时间种子/均匀漂移，
> GBM 固定种子与脉冲档为规划态）、`bench/ws-bench`（WS 客户端，连接/订阅可配，profile 分级与
> 多 pod 独立 IP 为规划态）、admin `/admin/bench/users|rules` 造数（即 user/rule seeder）。
> k6/wrk2 与 Chaos Mesh 原生集成未引入（混沌当前以删除 pod 手段演练，MTTR 9s 实测）。

## 4. 实验设计（论文六组实验）

### S1 吞吐实验

- 变量：tick 速率 1w → 5w → 10w → 15w/s（阶梯升压，每档持续 10min）
- 观测：Flink 各算子反压、Kafka lag、ingest 写入速率、CK 写入延迟
- 指标：**最大稳定吞吐**（无持续反压上限）；验证 ≥ 10w/s

### S2 端到端延迟实验

- 打点：生成器写 `gen_ts` → 逐段透传（gateway/kafka/flink/notify/ws_push）→ 客户端回传 `recv_ts`，客户端 NTP 同步 + 时钟偏移校正（同机房可忽略）
- 变量：负载档位 × 规则量（10w/50w/100w）
- 输出：延迟分解瀑布图 + P50/P95/P99 曲线；验证 P99 < 2s（价格类规则）

### S3 并发连接实验

benchmark-small 验证 10 万连接；benchmark-large 验证百万连接。两者分别记录实测值，不将 small 的资源数据外推为 large 的实测结果。

- 变量：连接数 10w → 50w → **100w**（与 ADR-014/docs/05 §2 分级序列统一；每档稳定 15min）；订阅 profile 按分级模型（10% FULL/30% SLOW/60% ALERT_ONLY）
- 观测：ws-gateway 内存/CPU（对照 28KB/连接预算）、连接-内存线性度、推送帧速率、集群 egress（对照 10Gbps 上限）、Kafka ws_push 吞吐、Redis 路由读写延迟
- 专项子实验：
  - S3a 单机密度：单实例按 20w 规划并记录连接-内存曲线与 GC 停顿（Go GOGC/GOMEMLIMIT 调优前后对比）
  - S3b 重连风暴：kill 1 实例（按实际承载连接数）→ 验证恒速准入 + 抖动退避，保留窗口内告警可补拉，集群无级联雪崩
  - S3c 长稳：100w 连接 + 分级推送持续 2h，内存无泄漏、FD 稳定
- 输出：连接容量曲线、egress 实测 vs 分级模型推算、重连恢复时间线

### S4 查询性能实验

- 变量：缓存命中率（冷/热）、数据量（10/100/500 亿行）、并发（1k→1w QPS）
- 输出：缓存命中 P99 < 10ms 验证；Doris 分区裁剪效果（扫描行数对比）；缓存命中率-吞吐曲线

### S5 扩展性实验

- 变量：Flink TM 1→2→4→8；ws-gateway 2→4→8；ingest 1→2→4
- 固定：负载 10w tick/s
- 输出：**加速比曲线**（目标线性度 ≥ 0.7）；Kafka 分区再平衡开销记录

### S6 故障演练（混沌）实验

- 场景：docs/02 §4.2 故障矩阵全量执行，每项 5 次取均值
- 输出：MTTR 分布、告警丢失数（目标 0）、数据丢失数（ingest 死信计数）、客户端恢复时间线图
- 亮点实验：**kill Flink 全部 TM** → 验证 checkpoint 恢复后规则状态完整（100w 规则版本对账一致）

## 6. 通过标准（验收线）

| NFR | 验收方法 | 通过线 |
|---|---|---|
| NFR-1 | S1 | ≥ 10w tick/s 稳定 30min |
| NFR-2 | S2 | P99 < 2s |
| NFR-5/6 | S3 + seeder | small：10w 连接/100w 规则；large：100w 连接/100w 规则 |

| NFR-8 | S6 | 单组件 MTTR < 5min |
| NFR-9 | S6 | 服务端事件丢失 0，保留窗口内客户端可补拉 100% |
| NFR-10 | S5 | 线性度 ≥ 0.7 |
